# 2026-11-16｜第三阶段开发与验收

第三阶段代码与本地联调已完成；**真实免费视觉模型识别验收仍待用户可用账号、密钥和网络环境**。当前没有调用真实模型，不能把本地模拟响应测试表述为实际食物识别成功。按用户授权，先推送当前成果，再继续不依赖模型凭据的界面完善与 APK 打包。

## 实现

- 独立 FastAPI 服务，提供鉴权健康检查与图片二进制上传接口，不保存照片或饮食数据。
- 后端校验输入格式、5 MB 大小与像素数，重新编码 JPEG、移除 EXIF，在内存中完成处理。
- Gemini 免费层优先，限定已核对有免费层的模型；必须显式确认项目没有启用计费。
- OpenRouter 仅接受明确的 `:free` 视觉模型，查询模型目录核对零价格与图像输入，禁用回退及付费价格。
- 配额不足立即提示，不自动重试模型、不切换付费模型；异常结果不进入本地数据库。
- 统一返回 foods / total_calories / notes，校验有限非负数值，合计由明细重算；只在本地尝试去除一次 Markdown 围栏。
- 手机支持拍照、相册、预览、压缩和取消；只清理应用缓存中的临时文件，不删除相册原图。
- Android 拍照进程被回收后的图片恢复入口，恢复后仍需用户点击识别和确认。
- 服务连接地址与个人令牌使用系统安全存储，模型密钥只放 Python 环境变量/本地 `.env`。
- 首次识别告知第三方图片处理与免费服务政策；用户不同意不会上传。
- AI 结果复用现有餐次编辑页，允许修改、添加和移除食物，确认保存之前不入账。
- 客户端仅允许局域网 IP 使用 HTTP，外网必须 HTTPS，禁止请求重定向。
