# 2026-11-16｜第二阶段开发与验收

第二阶段完成：个人资料、BMI、每日预算与手动饮食记录可以离线使用。按用户最新授权，验收并推送后继续第三阶段，无需逐阶段确认。

## 实现内容

- SQLite 五张表：user_profile、weight_records、daily_budgets、meal_records、food_items。
- 首次填写昵称、身高、体重和预算；资料可修改，BMI 自动显示一位小数。
- 修改体重时保留记录，不重复写入相同体重。
- 每日独立预算快照；更改默认预算前补齐启用以来未打开日期的旧预算，当天采用新预算。
- 补记启用前的日期时，采用最早保存的预算并建立快照；不会凭空推测当时的个体需求。
- 支持多种食物、四种餐次、历史日期补记、编辑食物/餐次/日期及整餐删除。
- 汇总只计算已确认保存的食物，超预算显示超出的具体数值；保留小数计算，显示时取整。
- 新增、修改、删除使用事务；餐次删除通过外键级联清理明细；保存按钮有重复提交保护。
- 数据或输入错误时保留已有记录/当前输入，并提供重试；保存期间不能退出编辑页。
- 午夜及应用回到前台时刷新日期和汇总。
- 禁用 Android 系统自动备份，个人数据库保留在本机；源码忽略数据库文件。

## 实际验证

- `scripts/dev.ps1 analyze`：通过，无静态检查问题。
- `scripts/dev.ps1 test`：8 项测试通过（5 项数据库测试、3 项界面测试）。
- BMI 样例：170 cm、65 kg → 22.5。
- 热量样例：1800 − 350 − 700 = 750 kcal；覆盖超预算和编辑/删除后重新汇总。
- 真正关闭并重新打开 SQLite 文件后，资料与饮食明细保持不变。
- 数据库写入故障注入：替换明细失败后，原食物与原餐次一起保留。
- 多食物表单合计更新，连续点击确认保存只产生一条餐次记录。
- Android x64 Debug APK 构建成功，在 Android 16 / API 36 模拟器安装并启动。
- 模拟器实际操作：填写 Kaka / 170 cm / 65 kg / 1800 kcal，保存 Rice / 230 kcal，强制停止并重启应用后仍显示已摄入 230、剩余 1570 kcal。
- [Android 重启后的实际页面](第二阶段截图/01_重启后今日.png)。这些资料均为验收样例，不是用户真实数据。

首次测试所需 SQLite Windows 二进制下载超时，已从依赖发布者的同一官方地址下载并按包内 SHA-256 校验后补入本地缓存，未修改依赖源码或依赖版本。
